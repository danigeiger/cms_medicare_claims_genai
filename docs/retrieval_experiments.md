# Retrieval Experiments

## Experiment 0 — Baseline

**Embedding model:** `sentence-transformers/all-MiniLM-L6-v2`

**Embedding text:**
- Variable
- Label
- Description

**Evaluation set:** 20 natural-language CMS variable queries

### Results

- Top-1 accuracy: 60%
- Top-3 accuracy: 80%
- Top-5 accuracy: 95%

### Observation

The embedding model generally identified the correct semantic category,
but sometimes struggled to distinguish closely related CMS variables.

Examples included attending, operating, rendering, and referring physician
variables. The distinguishing modifier in the variable label appeared to
have an important effect on retrieval ranking.


## Experiment 1 — Label Emphasis

**Embedding model:** `sentence-transformers/all-MiniLM-L6-v2`

**Embedding text:**
- Label
- Label
- Variable
- Description

The label was included twice to test whether giving it greater influence
would improve retrieval of closely related CMS variables.

### Results

- Top-1 accuracy: 60%
- Top-3 accuracy: 90%
- Top-5 accuracy: 100%

### Change From Baseline

- Top-1: no change
- Top-3: +10 percentage points
- Top-5: +5 percentage points

### Observation

Repeating the label did not improve Top-1 accuracy, but it improved
Top-3 and Top-5 retrieval.

Some individual variables improved substantially. For example,
`RNDRNG_PHYSN_NPI` moved from rank 3 to rank 1, while
`PRNCPAL_DGNS_CD` moved from rank 5 to rank 2.

Other variables became worse, showing that label emphasis alone does
not completely solve the ranking problem.

### Next Experiment

Test a second-stage reranking strategy on the candidates returned by
semantic search.

## Experiment 3 — Retrieval-Augmented Generation (RAG)

**Embedding model:** `sentence-transformers/all-MiniLM-L6-v2`

**Reranking model:** `cross-encoder/ms-marco-MiniLM-L-6-v2`

**Generative model:** `gpt-4.1-mini`

**Evaluation set:** 20 natural-language CMS variable queries

### Pipeline

1. Chroma retrieves the five most semantically similar CMS codebook documents.
2. The CrossEncoder reranks those five candidates.
3. `rag.py` formats the retrieved documents into context for the LLM.
4. GPT-4.1-mini identifies and explains the most relevant CMS variable.

### Results

- Correct answers: 19/20
- Preliminary accuracy: 95%

### Comparison With Previous Experiments

| Method | Top-1 / Answer Accuracy |
|---|---:|
| Baseline retrieval | 60% |
| Label emphasis | 60% |
| CrossEncoder reranking | 80% |
| Full RAG | 95% |

### Observation

The RAG pipeline identified the expected CMS variable in 19 of 20 generated answers.

Four questions that were not ranked first by the CrossEncoder were answered correctly by the LLM:

- `ADMTG_DGNS_CD`
- `ICD_PRCDR_CD25`
- `LINE_PLACE_OF_SRVC_CD`
- `RNDRNG_PHYSN_SPCLTY_CD`

This suggests that the LLM can identify the correct variable from multiple retrieved candidates even when the CrossEncoder does not rank it first.

### Failure Analysis

**Question:** What is the patient's race?

**Expected variable:** `BENE_RACE_CD`

**Result:** Incorrect

The LLM reported that the retrieved context contained physician identifier variables rather than information about beneficiary race.

This suggests a failure in the retrieval stage rather than an unsupported answer generated by the LLM.

### Evaluation Limitation

The current evaluation checks whether the expected CMS variable identifier appears anywhere in the generated response.

This can overestimate accuracy if the LLM mentions the correct variable but ultimately recommends a different one.

A stricter evaluation will extract the model's selected variable and compare it directly against the expected identifier.

### Next Steps

- Implement structured LLM output for more reliable evaluation.
- Investigate the failed `BENE_RACE_CD` retrieval.
- Test additional questions and ambiguous CMS terminology.
- Measure consistency across repeated evaluations.

### Conclusion

The full RAG pipeline achieved 95% preliminary accuracy on the 20-question evaluation set, compared with 80% Top-1 accuracy after CrossEncoder reranking and 60% for baseline semantic retrieval.

These results suggest that LLM-based generation can improve CMS variable identification when supplied with multiple relevant codebook documents.


## Experiment: Reciprocal Rank Fusion (RRF)

### Objective

Evaluate whether combining Chroma vector similarity rankings with CrossEncoder reranking improves retrieval performance for the CMS Medicare Claims GenAI system.

The experiment was motivated by a failure in the existing RAG pipeline: the question "Where was the service performed?" returned an incorrect variable despite Chroma initially retrieving the expected variable in first position.

### Experimental Setup

**Dataset:** CMS Medicare FFS Claims Codebook, containing 302 parsed variables.

**Evaluation set:** 20 natural-language questions, each paired with an expected CMS variable.

**Embedding model:** `sentence-transformers/all-MiniLM-L6-v2`

**Reranking model:** `cross-encoder/ms-marco-MiniLM-L-6-v2`

**Retrieval configuration:**
- Chroma retrieves the top 20 candidates.
- CrossEncoder reranks the 20 candidates.
- RRF combines the two rankings using a smoothing constant of `k = 60`.
- Top-1, Top-3, and Top-5 accuracy are calculated against the expected variable.

The experiments were implemented in:
- `src/retrieval/experiment_rrf.py`
- `src/retrieval/evaluate_rrf.py`

### Results

| Retrieval Strategy | Top-1 Accuracy | Top-3 Accuracy | Top-5 Accuracy |
|---|---:|---:|---:|
| Chroma | 60% (12/20) | 90% (18/20) | 100% (20/20) |
| CrossEncoder | **75% (15/20)** | 90% (18/20) | 95% (19/20) |
| Reciprocal Rank Fusion | 70% (14/20) | **100% (20/20)** | **100% (20/20)** |

### Failure Analysis: Place of Service

**Query:** "Where was the service performed?"

**Expected variable:** `LINE_PLACE_OF_SRVC_CD`

The original Chroma retrieval ranked the expected variable first. However, the CrossEncoder demoted it to sixth place, excluding it from the five candidates provided to the language model.

| Strategy | Expected Variable Rank |
|---|---:|
| Chroma | 1 |
| CrossEncoder | 6 |
| RRF | 1 |

RRF restored the expected variable to the top five.

However, the expected variable and `CLM_SRVC_FAC_ZIP_CD` received equal RRF scores. Their first-place ordering was determined by the stable sorting behavior of Python, rather than a meaningful difference in their fusion scores.

This illustrates an important limitation: the original question is ambiguous between the type of service setting and the geographic location of a service facility.

### Query Sensitivity

Three alternative phrasings were evaluated:

| Query | CrossEncoder Rank | RRF Rank |
|---|---:|---:|
| Where was the service performed? | 6 | 1 |
| What is the place of service code for a claim line item? | 1 | 1 |
| What type of setting was the medical service performed in? | 12 | 7 |

The CrossEncoder performed substantially better when the question closely matched terminology in the codebook.

This suggests that the reranking model may be sensitive to terminology and query phrasing, potentially reducing performance for users unfamiliar with CMS vocabulary.

### Interpretation

The CrossEncoder achieved the highest Top-1 accuracy (75%), while RRF achieved the highest Top-3 accuracy (100%).

Chroma and RRF both achieved 100% Top-5 accuracy. RRF therefore recovered the expected variable lost by CrossEncoder reranking without reducing Top-5 coverage on this benchmark.

Because the RAG system provides five retrieved candidates to GPT-4.1-mini, Top-5 accuracy is especially relevant.

However, improved retrieval coverage does not necessarily translate into improved final-answer accuracy.

### Limitations

- The benchmark contains only 20 questions.
- The evaluation questions were reused during experimentation, so these results do not demonstrate generalization to unseen queries.
- Some natural-language questions have multiple plausible interpretations.
- Equal-weight RRF does not resolve ties between conflicting rankings.
- The experiment evaluates retrieval accuracy, not the final answers generated by the language model.

### Conclusion and Next Steps

RRF is a promising alternative to CrossEncoder-only ranking, achieving 100% Top-3 and Top-5 retrieval accuracy on the existing benchmark.

The current production-style pipeline remains unchanged pending end-to-end evaluation.

**Next experiment:** Compare the existing Chroma → CrossEncoder → GPT-4.1-mini pipeline against Chroma → RRF → GPT-4.1-mini using the same evaluation questions and structured exact-match scoring.

A larger, independently constructed evaluation set should also be developed to assess performance on unseen natural-language questions.


## Experiment: End-to-End RAG Evaluation with RRF

### Objective

Determine whether the improved retrieval accuracy from Reciprocal Rank Fusion (RRF) translates into more accurate final answers from GPT-4.1-mini.

### Experimental Setup

Two RAG pipelines were evaluated using the same 20 CMS codebook questions:

- **Baseline:** Chroma → CrossEncoder → GPT-4.1-mini
- **Experimental:** Chroma → CrossEncoder + RRF → GPT-4.1-mini

Both pipelines used the same language model, instructions, structured output schema, and five retrieved context documents.

**Evaluation metric:** Exact-match accuracy between the predicted CMS variable identifier and the expected variable.

**Evaluation script:** `src/rag/evaluate_rrf_rag.py`

### Results

| Pipeline | Correct Answers | Accuracy |
|---|---:|---:|
| CrossEncoder + GPT-4.1-mini | 19/20 | 95% |
| RRF + GPT-4.1-mini | 20/20 | **100%** |

RRF improved end-to-end accuracy by 5 percentage points on the existing benchmark.

### Error Analysis

The only difference in final-answer correctness occurred for the question:

**"Where was the service performed?"**

Expected variable: `LINE_PLACE_OF_SRVC_CD`

- CrossEncoder pipeline predicted `CLM_SRVC_FAC_ZIP_CD`.
- RRF pipeline correctly predicted `LINE_PLACE_OF_SRVC_CD`.

The baseline reranker placed the expected variable sixth, excluding it from the five documents passed to GPT-4.1-mini.

RRF placed the expected variable first, allowing the language model to select it.

### Interpretation

The experiment demonstrates that retrieval-stage improvements can translate into better final-answer accuracy.

RRF achieved 100% Top-5 retrieval accuracy and 100% end-to-end exact-match accuracy on the 20-question benchmark.

However, the evaluation set is small, and its questions were used during retrieval development. These results do not establish performance on unseen questions.

Additionally, the service-location question has multiple plausible interpretations, and RRF produced tied scores for the place-of-service and facility-ZIP variables.

### Conclusion

RRF outperformed the CrossEncoder-only pipeline on the existing end-to-end benchmark without introducing additional incorrect answers.

RRF is the preferred candidate for further development, subject to validation on a larger, independent evaluation set.

**Next steps:**
1. Refactor retrieval to avoid duplicate Chroma queries.
2. Integrate RRF into the RAG pipeline while retaining the CrossEncoder baseline.
3. Evaluate both pipelines on unseen natural-language questions.
